# 深渊幸存者（Abyss Survivor）· 游戏设计文档

> 版本 v1.0 ｜ 2026-11-03
> 状态：已实现并通过自动化验证的部分见 §7

---

## 1. 一句话定位

**俯视角双人协作射击生存**——玩家在有限战场上移动射击，抵御一波波逼近的怪物，坚持到最终波次即为胜利。

- 单人可玩，联机时两个玩家共享同一批怪物、各自计分
- 玩法核心是"走位 + 射击"的节奏，不是数值堆叠
- 技术底座是**帧同步（Lockstep）**，两端逐帧一致

---

## 2. 核心循环

```
        ┌─────────────────────────────────────────┐
        │                                         │
   开始 → 战斗（第 N 波）→ 清理完该波 → 波次间隔 → 第 N+1 波
        │                    │                    │
        │                    └─ 玩家死亡 → 失败结算 ←┘
        │                                          │
        └──────────────────────────────────────────┘
                        胜利：撑过最终波次
```

一局游戏的时长由波次配置决定，目标是 5~8 分钟。

### 2.1 波次结构

| 波次 | 怪物数量 | 血量倍率 | 速度倍率 | 说明 |
|---|---|---|---|---|
| 1 | 3 | 1.0 | 1.0 | 教学波，只有追击 |
| 2 | 4 | 1.0 | 1.0 | |
| 3 | 5 | 1.2 | 1.05 | 血量开始成长 |
| 4 | 6 | 1.4 | 1.10 | |
| 5 | 7 | 1.6 | 1.15 | 出现"快速怪" |
| 6 | 8 | 1.8 | 1.20 | |
| 7 | 9 | 2.0 | 1.25 | 出现"高血怪" |
| 8 | 10 | 2.2 | 1.30 | |
| 9 | 11 | 2.5 | 1.35 | 混合怪 |
| 10（最终） | 12 | 2.8 | 1.40 | 撑过即胜利 |

波次参数全部在 `BATTLE_CONFIG.waves` 中以整数/定点数声明，**不随设备性能变化**，帧同步要求全体一致。

### 2.2 波间休息

清完一波后有 120 逻辑帧（2 秒）的间歇：
- 不刷怪
- 玩家血量**回复 10%**（给容错空间，但不足以鼓励无脑龟缩）

### 2.3 胜负条件

| 条件 | 判定 |
|---|---|
| **失败** | 任意玩家血量归零 → 全员结算（队友阵亡也算失败，保持"同生共死"的协作压力） |
| **胜利** | 撑过第 10 波的全部怪物并清空 → 胜利结算 |

## 3. 实体与数值

### 3.1 玩家

| 项 | 值 | 说明 |
|---|---|---|
| 血量 | 100 | 波间休息回复 10% |
| 移动速度 | 100 px/s | 摇杆力度线性映射到 0~100% |
| 射击 | 按住持续射击 | 攻击动画每 0.08s 一帧，第 2 帧触发出弹 |
| 子弹伤害 | 10 | |
| 子弹速度 | 300 px/s | |
| 受击冷却 | 0.5s | 防止被单帧秒杀 |

### 3.2 怪物

| 项 | 基础值 |
|---|---|
| 血量 | 20（受波次倍率影响） |
| 追击速度 | 80 px/s（受波次倍率影响） |
| 攻击范围 | 80 px |
| 击杀得分 | 10 × 波次 |

### 3.3 怪物类型（最终波次后解锁）

| 类型 | 血量倍率 | 速度倍率 | 外观区分 |
|---|---|---|---|
| 普通怪 | 1.0 | 1.0 | 原始外观 |
| 快速怪 | 0.7 | 1.6 | 体型缩小 20% |
| 高血怪 | 2.5 | 0.8 | 体型放大 30% |

类型由 `logicRng` 在刷怪时决定，**所有客户端消耗相同的随机序列**。

## 4. 状态机

### 4.1 怪物状态（五态，已实现）

```
        ┌──── 受击 ────┐
        │              ▼
   ┌────────┐      ┌──────┐
   │  Idle  │◄────►│ Hit  │
   └───┬────┘      └──────┘
       │ 移动
       ▼
   ┌────────┐◄────►┌────────┐
   │  Move  │      │ Attack │
   └────────┘      └───┬────┘
                       │ 血量 ≤ 0
                       ▼
                   ┌──────┐
                   │ Dead │ → 24 帧倒地 → 销毁
                   └──────┘
```

- `MonsterStateSystem` 是 `MonsterStateComponent` 的**唯一写入者**
- 状态时长全部以**逻辑帧**为单位，不含秒/浮点时间
- 表现是**纯函数** `evalMonsterVisual(state, 帧龄, seed, 朝向) → 变换量`，可重放、可回滚

### 4.2 对局状态（新增）

```
  Prepare ──► Fighting ──┬──► Victory（撑过最终波）
     │            │      │
     │            └──────┴──► Defeat（玩家阵亡）
     │                   │
     └───────────────────┴──► Paused（暂停 / 断线）
```

- `GameStateComponent` 持有当前对局状态、当前波次、分数
- 状态切换由 `GameStateSystem` 单点裁决
- 联机时对局状态由服务端同步（见技术文档 §5.3）

## 5. 操作

| 操作 | 设备 | 实现 |
|---|---|---|
| 移动 | 触屏摇杆（左半屏任意位置按下即生成摇杆） | `JoyStickManager` → `InputManager` → `LocalInputSource` 采样 |
| 射击 | 右下角 Shoot 按钮 | `InputManager.fireDown` |
| 暂停 | 预留 | — |

**输入采样时机**：`LocalInputSource` 在**逻辑帧边界**采样并量化为定点整数（方向 ×1000、力度 ×1000），保证帧同步下各端输入字节完全一致。

## 8. 数值调参入口

所有可调数值集中在 `assets/Script/game/Config/BattleConfig.ts`，分五个区：

| 区域 | 内容 |
|---|---|
| 时间 | 逻辑帧率、追帧上限 |
| 战场 | 战场半宽/半高 |
| 刷怪 | 刷怪间隔、出生边距、**波次表** |
| 玩家 | 血量、速度 |
| 怪物 | 血量、速度、攻击范围、类型倍率 |
| 子弹 | 速度、伤害、命中半径、回收边距 |
| 确定性 | 随机种子 |
| 网络 | 联机开关、服务端地址、最大人数 |

**调参纪律**：波次表里的值不得依赖分辨率、设备性能、真实时间。它们必须对所有客户端完全一致。
