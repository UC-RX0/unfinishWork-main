# 深渊幸存者（Abyss Survivor）· 游戏设计文档

> 版本 v1.0 ｜ 2026-11-03
> 状态：已实现并通过自动化验证的部分见 §7

---

## 1. 一句话定位

**俯视角双人协作射击生存**——玩家在有限战场上移动射击，抵御一波波逼近的怪物，坚持到最终波次即为胜利。

- 单人可玩，联机时两个玩家共享同一批怪物、各自计分
- 玩法核心是"走位 + 射击"的节奏，不是数值堆叠
- 技术底座是**帧同步（Lockstep）**，两端逐帧一致

---

## 2. 核心循环

```
        ┌─────────────────────────────────────────┐
        │                                         │
   开始 → 战斗（第 N 波）→ 清理完该波 → 波次间隔 → 第 N+1 波
        │                    │                    │
        │                    └─ 玩家死亡 → 失败结算 ←┘
        │                                          │
        └──────────────────────────────────────────┘
                        胜利：撑过最终波次
```

一局游戏的时长由波次配置决定，目标是 5~8 分钟。

### 2.1 波次结构

| 波次 | 普通 | 快速 | 高血 | 血量倍率 | 速度倍率 | 积分倍率 |
|---|---|---|---|---|---|---|
| 1 | 3 | - | - | 1.0 | 1.00 | 1.0 |
| 2 | 4 | - | - | 1.0 | 1.00 | 1.0 |
| 3 | 5 | - | - | 1.15 | 1.02 | 1.1 |
| 4 | 5 | - | - | 1.30 | 1.04 | 1.2 |
| 5 | 6 | - | - | 1.45 | 1.06 | 1.3 |
| 6 | 6 | 1 | - | 1.60 | 1.08 | 1.4 |
| 7 | 6 | 1 | 1 | 1.75 | 1.10 | 1.5 |
| 8 | 6 | 2 | 1 | 1.90 | 1.12 | 1.6 |
| 9 | 7 | 2 | 1 | 2.05 | 1.14 | 1.8 |
| 10（最终） | 7 | 3 | 2 | 2.20 | 1.16 | 2.0 |

全 10 波共 **69 只怪**。

波次参数全部在 `game/Config/WaveConfig.ts` 中以整数/定点数声明，**不随设备性能变化**，帧同步要求全体一致。

> **实测数据**（脚本 AI 躲避走位）：通关用时 9499 逻辑帧（约 2.6 分钟），69 杀 / 1743 分。
> 前 8 波几乎不掉血，最终波压力最大 —— 曲线是刻意设计的。

### 2.2 波间休息

清完一波后有 120 逻辑帧（2 秒）的间歇：
- 不刷怪
- 玩家血量**回复 15%**（给容错空间，但不足以鼓励无脑龟缩）

### 2.3 胜负条件

| 条件 | 判定 |
|---|---|
| **失败** | 任意玩家血量归零 → 全员结算（队友阵亡也算失败，保持同生共死的协作压力） |
| **胜利** | 撑过第 10 波的全部怪物并清空 → 胜利结算 |

## 3. 实体与数值

### 3.1 玩家

| 项 | 值 | 说明 |
|---|---|---|
| 血量 | 300 | 能挨 100 下（每次伤害 3） |
| 移动速度 | 100 px/s | 摇杆力度线性映射到 0~100% |
| 射击 | 按住持续射击 | 攻击动画 7 帧 x 0.04 秒 → **0.28 秒一轮** |
| 子弹伤害 | 10 | |
| 子弹速度 | 300 px/s | |
| 自动瞄准射程 | 380 px | 射程外的怪必须靠近才能被打到 |
| 受击冷却 | 1 秒（60 帧） | 防止被单帧秒杀 |

> **玩家速度必须略低于怪物速度**：玩家 100 / 怪 105。
> 玩家比怪快就能无限风筝（一直跑，怪永远追不上），
> 那样既没有被围攻的压力，怪也永远进不了攻击距离。

### 3.2 怪物

| 项 | 基础值 |
|---|---|
| 血量 | 20（受波次倍率与类型倍率影响） |
| 追击速度 | 105 px/s（受波次倍率影响） |
| 攻击范围 | 120 px |
| 停止追击距离 | 90 px |
| 攻击伤害 | 3 |
| 攻击冷却 | 1 秒（60 帧） |
| 击杀得分 | 类型基础分 x 波次积分倍率 |

> **停止追击距离 < 攻击范围**：这样怪会在"还能攻击但还没贴脸"的位置停下输出，
> 形成交战窗口。如果两个距离一样，怪永远走不到攻击距离，Attack 状态不会触发。

### 3.3 怪物类型

| 类型 | 血量倍率 | 速度倍率 | 外观缩放 | 基础分 |
|---|---|---|---|---|
| 普通怪 | 1.0 | 1.0 | 1.0 | 10 |
| 快速怪 | 0.7 | 1.6 | 0.8 | 15 |
| 高血怪 | 2.5 | 0.8 | 1.3 | 30 |

类型由波次表显式声明（不随机抽取），**所有客户端拿到完全一样的刷怪序列**。

## 4. 状态机

### 4.1 怪物状态（五态，已实现）

```
        ┌──── 受击 ────┐
        │              ▼
   ┌────────┐      ┌──────┐
   │  Idle  │◄────►│ Hit  │
   └───┬────┘      └──────┘
       │ 移动
       ▼
   ┌────────┐◄────►┌────────┐
   │  Move  │      │ Attack │
   └────────┘      └───┬────┘
                       │ 血量 ≤ 0
                       ▼
                   ┌──────┐
                   │ Dead │ → 24 帧倒地 → 销毁
                   └──────┘
```

- `MonsterStateSystem` 是 `MonsterStateComponent` 的**唯一写入者**
- 状态时长全部以**逻辑帧**为单位，不含秒/浮点时间
- 表现是**纯函数** `evalMonsterVisual(state, 帧龄, seed, 朝向) → 变换量`，可重放、可回滚

### 4.2 对局状态（新增）

```
  Prepare ──► Fighting ──┬──► Victory（撑过最终波）
     │            │      │
     │            └──────┴──► Defeat（玩家阵亡）
     │                   │
     └───────────────────┴──► Paused（暂停 / 断线）
```

- `GameStateComponent` 持有当前对局状态、当前波次、分数
- 状态切换由 `GameStateSystem` 单点裁决
- 联机时对局状态由服务端同步（见技术文档 §5.3）

## 5. 操作

| 操作 | 设备 | 实现 |
|---|---|---|
| 移动 | 触屏摇杆（左半屏任意位置按下即生成摇杆） | `JoyStickManager` → `InputManager` → `LocalInputSource` 采样 |
| 射击 | 右下角 Shoot 按钮 | `InputManager.fireDown` |
| 暂停 | 预留 | — |

**输入采样时机**：`LocalInputSource` 在**逻辑帧边界**采样并量化为定点整数（方向 ×1000、力度 ×1000），保证帧同步下各端输入字节完全一致。

## 6. HUD 与界面

> 全部用代码动态构建，不依赖美术资源（当前工程没有 UI 图集）。

| 元素 | 位置 | 内容 |
|---|---|---|
| 血条 | 左上角 | 当前血量 / 最大血量，绿→红渐变 |
| 分数 | 右上角 | 当前总分 |
| 波次 | 顶部居中 | `第 N / 10 波` + 波次进度 |
| 准备界面 | 全屏 | 标题 + "点击开始" |
| 结算界面 | 全屏 | 胜利/失败 + 总分 + 存活波次 + "点击重开" |
| 波次提示 | 顶部居中（短暂） | `第 N 波` 淡入淡出 |

## 8. 数值调参入口

所有可调数值集中在 `assets/Script/game/Config/BattleConfig.ts`，分八个区：

| 区域 | 内容 |
|---|---|
| 时间 | 逻辑帧率、追帧上限 |
| 战场 | 战场半宽/半高 |
| 刷怪 | 刷怪间隔、出生边距 |
| 对局流程 | 准备时长、休整时长、回血比例、连击时长 |
| 玩家 | 血量、速度 |
| 怪物 | 血量、速度、伤害、攻击范围、停止距离、攻击冷却 |
| 子弹 | 速度、伤害、命中半径、回收边距、**自动瞄准射程** |
| 确定性 | 随机种子 |
| 网络 | 联机开关、服务端地址、最大人数 |

波次表在 `assets/Script/game/Config/WaveConfig.ts`（与 BattleConfig 分开，因为它是数据而非参数）。

**调参纪律**：波次表里的值不得依赖分辨率、设备性能、真实时间。它们必须对所有客户端完全一致。

**调参方法**：改完数值后跑 `node tools/headless/game-flow-test.js`。
它会输出通关用时、击杀数、得分、血量轨迹 —— 用数据判断平衡，而不是靠感觉。
